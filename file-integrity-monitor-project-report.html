1 Abstract

This project presents a File Integrity Monitor (FIM) — a cybersecurity tool that detects unauthorised or unexpected changes to files within a monitored directory. The system computes SHA-256 cryptographic hashes of all files at a trusted point in time (the baseline) and subsequently compares fresh hashes against that baseline to identify modified, added, and deleted files.

The tool is delivered as a fully interactive web dashboard built with Python and Streamlit, requiring no database or external infrastructure. It includes real-time Auto-Scan Watch Mode, a persistent Scan History log, bar and line chart visualisations, CSV export, and an educational sidebar — making it suitable both as a practical security utility and as a demonstrable academic project.

2 Introduction

In modern computing environments, files are constantly at risk of tampering — whether from malware, insider threats, misconfiguration, or accidental modification. Detecting such changes quickly is a core requirement of security frameworks including PCI-DSS, HIPAA, and SOC 2, all of which mandate file integrity monitoring as a control measure.

A File Integrity Monitor addresses this by maintaining a cryptographic fingerprint of every monitored file. Because SHA-256 is a one-way function with an astronomically low collision probability, any change to a file — even a single character — produces a completely different hash value. This property, known as the avalanche effect, makes hash-based FIMs highly reliable for change detection.

This project implements a FIM entirely in Python using only the standard library for the core logic, with Streamlit providing the web-based user interface.

3 Project Objectives

  1. Implement SHA-256 file hashing in Python using efficient chunked binary reading.
  2. Build a baseline generation system that recursively snapshots an entire directory tree.
  3. Implement an integrity comparison engine that classifies each file as Clean, Modified, Added, or Deleted.
  4. Deliver results through an interactive, colour-coded web dashboard built with Streamlit.
  5. Add Auto-Scan Watch Mode for continuous, automated monitoring without user interaction.
  6. Maintain a persistent Scan History log and visualise violation trends over time.
  7. Keep dependencies minimal — streamlit and Python's standard library only.

4 Background & Theory

4.1 Cryptographic Hashing

A cryptographic hash function maps an input of arbitrary size to a fixed-size output (digest). SHA-256 (Secure Hash Algorithm 256-bit) is a member of the SHA-2 family standardised by NIST. It produces a 256-bit (64 hexadecimal character) digest and has the following properties relevant to integrity monitoring:

PropertyDescriptionRelevance to FIM
DeterministicSame input always produces same outputBaseline hashes can be reproduced and compared
Avalanche EffectTiny input change → completely different digestEven a 1-character edit is detected
Pre-image ResistanceCannot reverse-engineer the file from its hashSafe to store hashes publicly
Collision ResistanceComputationally infeasible to find two files with same hashFalse negatives are practically impossible

4.2 Avalanche Effect — Demonstration

Input A: hello world
SHA-256 A: b94d27b9934d3e08a52e52d7da7dabfac484efe04294e576...

Input B: Hello world  ← one character changed (h → H)
SHA-256 B: a591a6d40bf420404a011733cfb7b190d62c65bf0bcda32b...

The two digests share zero common leading characters — this is the avalanche effect in action.

4.3 Chunked File Reading

Rather than loading an entire file into memory before hashing, the implementation reads files in 64 KB chunks. This keeps memory usage constant regardless of file size, allowing the FIM to scan multi-gigabyte files without performance degradation. 

hasher = hashlib.sha256()
with open(filepath, "rb") as fh:
    while chunk := fh.read(65_536):   # 64 KB at a time
        hasher.update(chunk)
return hasher.hexdigest()

6 Features & Implementation

⚙️
Baseline Generation
Recursively scans a directory with Path.rglob(), hashes every file, and saves results to baseline.json as a portable JSON map using relative forward-slash paths.
🔍
Integrity Scan
Re-hashes all files, performs a set-union comparison against the baseline, and classifies every file as Clean, Modified, Added, or Deleted.
📊
Metric Cards + Bar Chart
Five summary metric cards (Total, Clean, Modified, Added, Deleted) with delta indicators, plus a bar chart breakdown of the current scan's status distribution.
🚨
Alert Banner
A prominent red error banner fires automatically when any violations are detected. A green success banner confirms when all files are clean.
📋
Results Table + Filter
An HTML table with colour-coded status badges, shortened hash previews, and a file path column. A dropdown filter narrows results by status category.
⬇️
CSV Export
One-click export of the current filtered results as a timestamped CSV file — ready for audit reports or evidence submission.
⚡
Auto-Scan Watch Mode
A sidebar toggle enables continuous monitoring. A configurable interval slider (10s–5min) controls the scan frequency. A live countdown timer updates every second.
🕓
Scan History Log
Every scan appends a summary to scan_history.json (capped at 50 entries). A trend line chart and expandable history table appear at the bottom of the dashboard.

7 Status Classification Logic

StatusConditionThreat Represented
🔴 Modified File exists in both baseline and current scan, but hashes differ File content tampered — malware injection, config manipulation
🟡 Added File present in current scan but absent from baseline Unauthorised file dropped — malware payload, backdoor
⚪ Deleted File present in baseline but absent from current scan File removed — log wiping, evidence destruction, sabotage
🟢 Clean File present in both; hashes match exactly No change — file integrity confirmed

9 Auto-Scan Watch Mode — Design

Watch Mode implements a continuous monitoring loop using Streamlit's st.rerun() mechanism. When enabled, the system:

  1. Runs an immediate first scan upon activation.
  2. Records the scan timestamp in st.session_state.
  3. Displays a live countdown timer (updated every second via time.sleep(1)).
  4. When the countdown reaches zero, runs a fresh scan and calls st.rerun() to refresh the dashboard.
  5. The loop continues until the user disables the toggle.
Available intervals: 10s · 15s · 30s · 60s · 2 minutes · 5 minutes
State persistence: Results are stored in st.session_state so they survive widget interactions between scans.
Note: The manual scan button is automatically disabled while Watch Mode is active to prevent conflicting scan operations.

10 Session State Management

Streamlit re-runs the entire script from top to bottom on every user interaction (button click, dropdown change, toggle flip). Without careful state management, scan results would be lost every time the user interacts with a widget.

The solution uses st.session_state as an in-memory key-value store:

KeyTypePurpose
scan_resultslist[dict]Latest scan result rows — persists across filter changes
scan_directorystrDirectory that was last scanned
watch_enabledboolWatch Mode on/off state
watch_intervalintSelected auto-scan interval in seconds
watch_last_scanfloatUnix timestamp of the last auto-scan

12 Security Considerations

12.1 Strengths

  • SHA-256 collision resistance — practically impossible to create a modified file with the same hash, ensuring no tampering goes undetected.
  • Chunked reading — prevents memory exhaustion attacks through large files.
  • Relative path storage — baseline is directory-agnostic and portable.
  • Permission-safe — unreadable files are silently skipped rather than causing crashes.

12.2 Limitations & Future Improvements

LimitationPotential Improvement
Baseline file itself could be tamperedSign the baseline with HMAC or store it on a separate read-only location
No real-time filesystem event hookIntegrate OS-level watchers (watchdog library) for instant notification
Local dashboard onlyAdd email / Slack alerting via SMTP or webhook when violations are detected
No user authenticationAdd login protection before deploying on a shared server
SHA-256 is not HMACUse HMAC-SHA256 with a secret key to also authenticate the hash source

13 Setup & Usage

13.1 Installation

pip install streamlit
streamlit run File_Integrity_Monitor.py

The browser opens automatically at http://localhost:8501.

13.2 Workflow

  1. Enter the full path of the directory to monitor in the "📁 Directory to Monitor" field.
  2. Click ⚙️ Generate Baseline — creates baseline.json with SHA-256 hashes of all files.
  3. Click 🔍 Run Integrity Scan — compares current state against the baseline.
  4. Review metric cards, alert banner, bar chart, and results table.
  5. Use the status filter dropdown to narrow results by category.
  6. Click ⬇️ Export Results as CSV for reporting.
  7. Enable Watch Mode in the sidebar for continuous automated monitoring.
  8. Scroll to the bottom to review Scan History and violation trend chart.

14 Conclusion

This project successfully implements a fully functional, web-based File Integrity Monitor that demonstrates core cybersecurity principles including cryptographic hashing, the avalanche effect, baseline-comparison integrity checking, and continuous monitoring.

The tool is practical, requiring only a single Python file and one pip install to operate. It covers all three NIST-defined integrity event categories (modification, addition, deletion), provides clear visual feedback through colour-coded alerts and charts, and maintains a persistent audit trail through the scan history log.

The addition of Auto-Scan Watch Mode elevates the project beyond a simple utility into a genuine near-real-time monitoring system, demonstrating how cryptographic hashing can be applied continuously to protect a file system against tampering — the same principle used by enterprise security products such as Tripwire, AIDE, and AWS CloudTrail.
